# 아키텍처 결정 기록

## ADR-001: Spring Boot 3.5.16 유지보수 계열

- 상태: 채택
- 결정일: 2026-07-23
- 결정: Java 21과 호환되는 Spring Boot 3.5.16을 사용한다.
- 이유: 4.x 최신 기능보다 과제에서 요구한 Spring MVC, Security, JPA, Thymeleaf 생태계의 성숙성과 호환성을 우선한다.
- 결과: Jakarta API와 Spring Security 6 모델을 사용한다.

## ADR-002: 서버 렌더링 모놀리스와 서버 세션

- 상태: 요구사항으로 채택
- 결정: 단일 Spring MVC 애플리케이션, Thymeleaf, 서버 세션을 사용한다.
- 이유: JWT/localStorage, SPA, WebSocket, 마이크로서비스를 제외해 인증과 공격 표면을 단순화한다.

## ADR-003: PostgreSQL 17.10과 Flyway 단독 스키마 관리

- 상태: 채택
- 결정: 운영·개발·테스트 모두 PostgreSQL 17.10을 사용하고 `ddl-auto=validate`로 Flyway 스키마와 Entity를 검증한다.
- 이유: 실제 DB 제약과 행 잠금/동시성 의미를 보존하면서 Spring Boot 3.5.16 관리 Flyway 11.7.2의 공식 시험 범위에 맞춘다. 최초 18.4 기동에서 호환성 경고를 확인해 지원되는 최신 17.x 마이너로 조정했다.

## ADR-004: UUID 외부 식별자와 내부 관계 검증

- 상태: 채택
- 결정: 도메인 ID는 UUID를 사용하되 모든 변경/비공개 조회는 소유자·참여자 조건을 함께 검증한다.
- 이유: UUID는 권한 경계가 아니므로 IDOR를 Service와 Repository 양쪽에서 방지해야 한다.

## ADR-005: 이미지 재인코딩과 애플리케이션 전용 조회

- 상태: 채택
- 결정: JPEG/PNG/WebP를 검증한 뒤 안전한 PNG 또는 JPEG로 재인코딩하여 실행 경로 밖에 UUID 키로 저장한다.
- 이유: 원본 파일명, polyglot/위장 MIME, 손상 파일, 경로 순회 위험을 줄인다.
- 대안: 오브젝트 스토리지는 과제 범위와 외부 서비스 의존성 때문에 채택하지 않는다.

## ADR-006: DB 기반 제한 조회 대화

- 상태: 요구사항으로 채택
- 결정: 메시지는 PostgreSQL에 저장하고 화면 새로고침 기반으로 조회한다.
- 이유: WebSocket 없이도 요구사항을 충족하며 권한과 감사 경계를 단순하게 유지한다.

## ADR-007: 송금 intent와 결정적 지갑 행 잠금

- 상태: 채택
- 결정: 3분 유효 intent, 재인증, idempotency unique key를 사용하고 두 지갑 UUID 순서로 `FOR UPDATE` 잠금을 획득한다.
- 이유: 클라이언트 변조, 중복 차감, 잔액 경쟁, 교착 위험을 줄이고 복식 원장 무결성을 보장한다.

## ADR-008: 실제 금융정보 비수집

- 상태: 요구사항으로 채택
- 결정: 닉네임과 정수형 교육용 가상 포인트만 사용한다.
- 이유: 실제 결제/금융 서비스가 아니며 민감 금융정보 수집은 목적에 불필요하다.

## ADR-009: Git 작업과 외부 배포 보류

- 상태: 채택
- 결정: 사용자 승인 전에는 Git 초기화, commit, push, 저장소 공개, 배포를 하지 않는다.
- 이유: 첨부 요구사항이 해당 작업 전에 명시적 확인을 요구한다.

## ADR-010: 누락 기준 문서 처리

- 상태: 채택
- 결정: 존재하지 않는 `AGENTS.md`와 `outputs/PROJECT_BLUEPRINT_KO.md` 내용을 추측하지 않고 첨부 요구사항을 기준으로 진행한다.
- 이유: 비어 있는 저장소에서 원본 문서 내용을 창작하면 추적성과 정확성을 해친다.

## ADR-011: 로컬 JDK 23의 Java 21 release 모드

- 상태: 채택
- 결정: 소스/대상 호환성과 `javac --release`는 21로 고정한다. 로컬은 설치된 JDK 23으로 컴파일하고 GitHub Actions는 실제 Temurin 21을 사용한다.
- 이유: 로컬에 JDK 21이 없고 JDK 23만 설치되어 있다. `--release 21`은 Java 21 API와 class 형식을 강제하며, CI의 JDK 21 실행으로 런타임 호환성을 보완한다.
